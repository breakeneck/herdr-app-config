# Herdr — що просили і що зроблено

Сесія: 9 листопада 2026. Конфіг: `~/.config/herdr-app` (моди в `mods/`).

---

## 1. Remote Projects — тогл по кліку в хедері

**Просив:** вкладка Remote Projects — зробити змогу тоглити, щоб по кліку в хедері вони ховались.

**Зроблено:**
- У хедері (мод `mods/tabs-copy`) з'явилась кнопка **Projects** — клік ховає/показує секцію Remote Projects.
- Заголовок **REMOTE PROJECTS** у самій секції теж клікабельний — клік ховає секцію.
- Pitfall, який обійшли: `layout.toggle` повертає `ok`, але на ваговій сайдбар-секції нічого не робить — використано явні `layout.hide` / `layout.show`. Прихований стан runtime-only (не персистується).

## 2. Changes — відкриття діфу в головному просторі (PhpStorm-style)

**Просив:** коли клікаєш на змінений файл, він має відображатись на основному спейсі посередині (бо там широке відображення), зі змінами зліва і справа — «як було і як стало», у стилі PhpStorm, з кнопками наступна/попередня зміна.

**Зроблено:**
- Новий мод **`mods/diff-view`** — таб у головному просторі.
- Клік по файлу в панелі Changes відкриває/перевибирає цей таб (`openMain()`: один diff-таб на спейс — через `panes()`, `tab.select` + `setShared("diff.request")`, або `tab.new {mod:"diff-view", props}`).
- Side-by-side: ліва колонка — стара версія (зі знаками `-`), права — нова (`+`), підсвітка ханків, синтаксична підсвітка коду (скопійований `highlight.js`).
- Кожна колонка має **власний горизонтальний скрол**, вертикальний — спільний; стрілки prev/next (+ Alt+↑/↓) стрибають по змінах.

## 3. Перегляд цілого файла в діф-вью

**Просив:** додати в діф-вью перегляд цілого файла — не відрізаний шматок, а весь файл; кнопочку біля стрілок, які навігують по змінах; стрілки в цьому режимі просто стрибають по змінах.

**Зроблено:**
- У хедері діф-вью дві кнопки режиму поруч зі стрілками: **diff** (тільки змінені ханки, `-U3`) і **file** (весь файл, `-U1000000`, зміни підсвічені).
- У file-режимі стрілки prev/next стрибають по runs змін усередині повного файла.

## 4. Генерація commit message

**Просив:** кнопка «згенерувати коміт меседж», у ній справа тонкий дропдаун з іншими можливостями, і там пункт Settings, де можна описати яку модель використовувати — Claude по підписці чи локальну.

**Зроблено:**
- Спліт-кнопка **Generate** з шевроном/меню (Settings…).
- Налаштування зберігаються в shared-стані `commit.gen` = `{provider, command, args, model, url}`.
- Генерація запускає налаштовану CLI-команду через `exec(..., {cwd: root, on: machine})` — працює і для remote-репо.

## 5. Налаштування: показ/ховання, локальні моделі, Claude в папці репо, дропдаун моделей

**Просив:** старий inline прев'ю змін прибрати (не потрібен); вікно генерації не пропадало — зробити щоб налаштування показувались і ховались; модель не лише Claude, а й локальна; Claude має стартувати в поточній папці; модель вибирати з дропдауна — від найновіших до найстаріших.

**Зроблено:**
- Inline прев'ю змін у панелі Changes **прибрано** — клік по файлу тільки відкриває діф у головному просторі.
- Налаштування генерації перенесені **в саму панель Changes** (блок COMMIT GENERATION): ховається/показується хрестиком × (shared `gen.settings`, за замовчуванням показаний) і з меню Generate ▾ → Settings.
- Перемикач **Source: Claude (subscription) / Local**.
- Локальні моделі: поле URL (дефолт `http://localhost:11434/v1`), список тягнеться з OpenAI-compatible ендпоінту `GET /v1/models` і сортується від найновіших.
- Дропдаун моделей для Claude: CLI default / fable / opus / sonnet / haiku — newest-first.
- Claude запускається з `cwd` = папка репо (на потрібній машині), у блоці є підказка: `Runs 'claude -p' inside the repo folder on server`. Перевірено на server: `claude -p` відповідає.

## 6. Commit message — TextArea замість тонкого інпуту

**Просив:** писати коміт меседж у текст ареа, а не в тонкому інпуті.

**Зроблено:**
- `InputState` → **`TextareaState`/`Textarea`** (gpui-base). Enter = коміт, Shift+Enter = новий рядок.

## 7. Сплітер для поля commit message

**Просив:** додати можливість розтягувати віконце з коміт меседжем, спліттер тіпа постав.

**Зроблено:**
- Над textarea — drag-ручка (`cursor_row_resize`, tooltip): тягнеш — поле росте від 2 до 16 рядків; висота зберігається в localStorage (`commitRows`).

## 8. Remote Projects — діалог вибору папки

**Просив:** не вписувати шлях вручну, а відкривати діалог вибору папки.

**Зроблено:**
- Новий мод **`mods/folder-picker`** — діалог «Choose a folder»: поле шляху, навігація `../`, список папок; браузериться по тій машині, якій додаєш проєкт (і по Mac, і по server — через `exec(..., {on: machine})`).
- У секції Remote Projects біля поля шляху — іконка-кнопка папки; вибрана папка повертається через shared `folder.pick` і додається як проєкт.
- Виправлений баг: `cd '~'` падав (тильда в лапках не розкривається) — тепер `"$HOME"` коректно.

## 9. Вибір бренчу — дропдаун замість оверлея

**Просив:** навіщо там оверлей? хай просто буде дропдаун.

**Зроблено:**
- Branch-picker (мод `mods/branch-picker`: фільтр, дерево локальних бренчів з групами `prefix/`, секція Recent, ↑↓/↵ checkout) тепер відкривається як **`kind: "popup"`** — прикріплений дропдаун під чипом бренчу в хедері, а не центрований діалог-оверлей.

## 10. Примара старої панелі налаштувань справа

**Скаржився:** справа висить панелька налаштувань коміту, нічого її не тоглить і не закриває, плюс помилка.

**Причина і фікс:** старий діалог `commit-settings` завис «примарою» — його мод-директорію видалили, поки діалог був відкритий; копія програла помилку рендеру і випала з реєстру оверлеїв, тому закрити її було неможливо. Залишено невидиму заглушку `commit-settings` (`div().size(0)`, + спроба закрити себе при перезавантаженні) — помилка зникла; повністю примара зникне після перезавантаження вікна herdr.

## 11. Тогл Agents, примара справа, налаштування генерації — у вікні

- У хедері кнопка **Agents** (поруч із Projects) ховає/показує список агентів. Обидва тогли — `layout.hide`/`layout.show`, стан зберігається між перезапусками (`layouts/.state/remote.json`).
- «Примара» справа була не оверлеєм, а блоком `commit-settings` у `layouts/remote.json` (Herdr сам пристикував мод, бо його папку побачив раньше, ніж `mod.json` з `"place": "none"`). Блок прибрано. **Pitfall:** новий мод — спершу `mod.json` з `"place": "none"`, потім `main.js`.
- Налаштування генерації — окреме вікно, мод **`mods/commit-gen`** (`kind: "window"`, `key: "commit-gen"`, перетягується, пам'ятає місце): Source, Server + ↻, Command/args, Model. Відкривається з Changes → Generate ▾ → Settings…. Inline-блок прибрано.
- Сплітер commit message: тягнеш ручку вгору — поле росте (40–420 px, `localStorage.commitH`). Нижня секція має явну висоту: розкладка недораховувала Textarea, і кнопки Generate/Commit випадали за низ панелі.

## 12. Згортання по тайтлу, Edit layout, Jira і PR

- Кнопки Projects/Agents з хедера прибрано. Будь-яка секція в колонці (Spaces, Remote projects, Agents, а також Files/Changes/Jira/PR, якщо їх перенести в сайдбар) згортається кліком по заголовку (▾/▸).
- **Edit layout** (справа в хедері, в режимі — «Done»): тягнеш блок за заголовок і відпускаєш на половині іншого блоку («↑ Put above» / «↓ Put below»). Працює і клік-клік: клік по заголовку бере блок, клік по половині кладе. Блок, кинутий на Files/Changes/Jira/PR у правій панелі, стає поруч зі стеком панелі. Кнопки панелей у хедері показуються тільки для блоків, які ще в стеку панелі.
- Логіка в `section.js` (одна копія в кожному з: spaces-copy, agents-copy, files-copy, changes-copy, remote-projects, jira, prs). Правити в `mods/spaces-copy/section.js` і копіювати в решту. Стан: shared `layout.edit`, `layout.drag`, `sections.collapsed`; структура змінюється через `layout.set`.
- `spaces`, `agents`, `files` склоновано в `*-copy` (вбудовані моди Herdr read-only). Клони не оновлюються з новими версіями Herdr.
- Встановлено моди **jira** і **prs** з github.com/gandriyko/herdr-app-config (у стеку правої панелі, кнопки Jira / PR). prs щохвилини викликає `gh`; jira тримає токен у Keychain (`herdr-jira`).

## 13. Баги Changes/diff-view, Jira по колонках, PR для GitLab

- Changes: клік по файлу завжди відкриває діф (раніше клік по авто-виділеному першому файлу знімав виділення). Прибрано ~270 рядків мертвого inline-прев'ю (`highlight.js` у changes-copy більше не використовується).
- diff-view: запит `diff.request` несе `space` — таб в одному спейсі не підміняє файл через клік в іншому; таб перейменовується на поточний файл; Alt+↑/↓ (`"up"`/`"down"`) + фокус по кліку; × закриває свій таб.
- Jira: групи = колонки дошки проєкту (`/rest/agile/1.0/board?projectKeyOrId=…` → `/configuration`), у порядку дошки; всередині — Rank (`ORDER BY Rank ASC`). Статус після назви прибрано (кольорова крапка лишилась). Перетягування таска на іншу колонку = Jira transition у статус цієї колонки (порожні колонки з'являються як цілі під час перетягування). Якщо workflow не дозволяє перехід — повідомлення з поясненням.
- PR: GitHub — як і було (`gh`); будь-який інший хост (git.<company>.com) — GitLab merge requests через REST API (`scope=created_by_me`), пайплайн як крапка, `detailed_merge_status` як мітка (ready / review / threads / conflict…). Токен (read_api) — у Keychain `herdr-gitlab`, account = хост; форма в панелі при першому відкритті.

## 14. Jira: порожні колонки, попап таска; PR: All / Mine

- Jira: порожні колонки дошки тепер видно завжди (раніше `render` відфільтровував їх ще до перевірки драгу, тож вони не з'являлися ніколи); пошук ховає порожні. Старт драгу ловлять і рядки (`on_mouse_move` / вихід з рядка), і колонки (`on_hover` → `this.over`); кидок — на `mouse_up` кореня за `this.over`.
- Клік по таску відкриває діалог (той самий мод `jira` з `props.issue`): статус, assignee/reporter/priority/parent/labels, опис і коментарі (ADF → markdown, `adf()`), кнопки Open in Jira / Copy key.
- PR: перемикач **All / Mine** (за замовчуванням All, `localStorage.mine`). Раніше показувались тільки «мої» — у мене відкритих MR 0, тому панель була порожня. В режимі All у рядку видно автора.
- Діагностика: GitLab за Cloudflare; Python urllib отримує 403 «error code: 1010» (банить UA), curl і fetch мода — ок.

## 15. PR: миттєве перемикання між проєктами

- Перехід у інший спейс (або `cd` у терміналі — перевірка раз на 2 с) одразу показує список того репо з кешу; якщо список старший за 30 с або його нема — у фоні оновлюється тільки це репо (`refreshOne`), а не всі.
- Кеш у `localStorage` мода `prs`: `cache:all` / `cache:mine` (списки з часом `at`), `remotes` (папка → репо, щоб не питати `git remote` знову). Переживає перезапуск. Помилки й запити токена не кешуються.
- Щохвилинне повне опитування лишилось; воно теж оновлює кеш.

## 16. Trello у панелі Tasks, гаряче оновлення Jira, шаблон коміт-меседжу

- Кнопка **Jira** в хедері тепер **Tasks**. Джерело тасків вибирається для кожного проєкту (репо за origin) перемикачем **Jira / Trello** у заголовку панелі; вибір і дошка — у shared `tasks.sources` (не в репо).
- Trello (`mods/jira/trello.js`): підключення — API key (Power-Up admin) + token (кнопка Get token), у Keychain `herdr-trello`. Списки дошки як колонки (порядок дошки й карток), All / Mine, перетягування картки на інший список (`PUT /cards/{id}?idList=…&pos=top`), клік — попап з описом (markdown), чеклістами й коментарями. Дошку проєкту змінює чип з назвою дошки.
- Гаряче оновлення: Jira-список і колонки кешуються (`localStorage jira:cache`), Trello — кожна дошка (`trello:board:<id>`); при перемиканні проєкту панель одразу показує кеш і оновлює у фоні, якщо він старший за 30 с.
- Коміт-меседж: у вікні налаштувань генерації поле **Template** (формат, який просимо в моделі; дефолт — перший рядок ≤72 символи, далі пункти «- …» без порожніх рядків) і галочка **No blank lines** (за замовчуванням увімкнена: порожні рядки прибираються з відповіді моделі).
